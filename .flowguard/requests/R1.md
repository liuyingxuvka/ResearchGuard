# ResearchGuard 方案清单（第十一轮：第 0 阶段 0.5.17 → 0.6.0；第 3 阶段 0.6.0 → 0.6.1）

## 这份清单要达到什么（方案总览）

ResearchGuard 管的 AI 弱点是：**说出一个原因或一个数字，而没有任何来源支撑它**。它的做法是把一个研究问题拆成几份互相独立的记录（来源模型、时间线、论证、实验），要求它们彼此对得上，再给出“能断言 / 要加限定 / 必须保留”的结论（`root_claim: h_suez: withhold`）。规划阶段的试验说明：只有当 AI 的说法必须对上一份**它在同一口气里没写的记录**时，这个工具才真的拦得住错（设计说明 §4 开头的原则；包里的 `findings/skills11-rl.md` E2）。这一轮第 0 阶段就补这个地方，第 3 阶段把自己的模型系统升级到 FlowGuard 1.0。

### 0.7 固定命令（原样复制；条目里用括号里的名字指它们）

- 【定向测试】`python -m pytest -q <条目列出的测试>`：没有 `failed`，没有 `error`。
- 【地图检查】`python -m flowguard map check --root . --strict`：最后一行 `check: 0 error(s), ...`。
- 【变更】`python -m flowguard change --run`：只用于路线 (a0)。修掉每个 `ERROR`；`REVIEW`、`promises:`、字面量提示行，每行都打开它点名的地方处理，或在日志里写理由。
- 【目标开始】`python -m flowguard target start "<编号>: <条目写的英文目标>" --request R1`。
- 【加入目标】`python -m flowguard target add <模型 id>`：一次一个 id。
- 【设计检查】`python -m flowguard target check`：退出码 1 有错误，3 有待办，0 干净。
- 【提升】`python -m flowguard target promote`。
- 【模型】`python -m flowguard map models <id> ...`：每个模型一行 `PASS`，最后一行 `models: N passed, 0 failed`。
- 【发布检查】`python -m flowguard release`：退出 0，最后一行以 `verify: PASS` 开头。
- 【提示检查】`python scripts/check_prompt_bundles.py`：打印 `pass`，退出码 0。
- 【安装检查】`python scripts/install_skill.py --target "$(mktemp -d)/skills"`，同一个目录再加 `--check`：退出码都是 0。
- 【规则块检查】`python -m flowguard template adoption > ../agents_block_now.txt; python $PKG/01_跨仓库_附件/check_agents_rules.py ../agents_block_now.txt AGENTS.md`：打印 `OK (6 rules)`（FlowGuard 清单 FG-618 要求 6 用的同一个脚本和写法）。

### 0.10 数字和卡住怎么办

- **数字**（主人的说明 H）：没有一个尺寸数字或秒数是通过不通过的标准，条目、第 5 节的行和你新加的测试都不用它们。一条路径变慢了、一段输出变长了，不算失败：在成本表的“差别去了哪里”一列写明多出来的去了哪里；是浪费就修。仍然是数字的只有已经强制的模型拆分触发（每个模型 8/12 条规则，FlowGuard 第 2 阶段换成功能触发）：本清单给旧模型加规则时都算过，做完以后没有一个模型超过 8 条规则（第 4.2 节）。
- 验证结果和清单不符：照 `00_先读我.md` 的“卡住怎么办”；撤掉没提交的改动用 `git restore --staged --worktree .`，新文件用 `git clean -fd -- <路径>`，放弃一个还没推送的目标用 `python -m flowguard target drop --yes`。
- **按定义判断，不按预计行。** 本清单“应看到”里新建的信息原文是要求，必须一字不差；规划阶段对 FlowGuard 缺口行的预计（`v0.71.0` 在规划阶段还不存在）对不上时，按 0.5 写的定义判断，把预计、实际和依据写进日志；不符合定义才算失败。
- 仍然不符：停在这一步，**不发布**；命令、完整输出和停下的位置写进日志和最终报告。
- 不放松、不删已有的功能断言；不删用例或已知坏；不为了时间解绑测试。示例被同步（RG-603）以后，测试里从示例算出来的具体值（例如 `tests/test_research_views.py` 第 52、55 行的 `0.25`）换成同步后真算出来的值，断言的意思不变：这不是放松。
