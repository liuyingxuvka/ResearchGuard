# Broad Depth and Closure

Broad LogicGuard wording requires current target-owned evidence over the complete declared argument universe.

Before building a real model, freeze a target-local `logicguard.target_model_purpose_declaration.v1`: exact prevented failures, bounded claim, candidate path, and one current native oracle plus target-owned known-good/known-bad case per failure. Late, stale, empty, non-blocking, or family-baseline-substituted declarations block. There is one enforced route and no lighter profile or fallback.

Maintain a closure ledger with model-card coverage, high-importance gaps, postwrite status, skips, safe wording, and unsafe boundaries. High-importance claims need connected claim-local support, warrant, assumption, boundary, and opposition or explicit target-authored closed dispositions. Implicitly shared role nodes, unresolved comparable conclusions, untested applicable perturbations, omitted target units/cards, shallow important cards, and a missing competition disposition remain gaps.

Run `researchguard logic depth <model> --output <receipt>` after the last meaningful model change. Broad claims require the native broad profile and current model plus authoritative-universe fingerprints. Callers cannot raise the importance threshold or shrink the denominator. Every governed obligation keeps its target-native semantic object, evidence reference, and lowercase content hash; counts and whole-receipt hashes are not per-obligation proof.

Run the closure helper when an aggregate ledger exists. `partial`, `blocked`, or `downgraded` results require the named next action or narrower wording. A repository regression proves capability only, never the current task. Broad wording is licensed only when `broad_claim_licensed: true` and all current gaps are closed.
