# LogicGuard domain blueprint contract

Load this only for explicit blueprint qualification, reconstruction scope, interface review, impact, reverse trace, or export. The existing H-WADF model, validator, depth owner, and purpose proof remain authoritative; this contract adds no second argument solver.

## DNA ownership boundary

This blueprint is LogicGuard member-domain DNA: it owns argument, artifact, claim-support, interface, evidence-role, and native closure semantics. It may supply semantic obligations to the LogicGuard subtree under the sole FlowGuard-owned ResearchGuard repository software-DNA root, but it is not a whole-repository software blueprint. Code, test, intent, resource, topology, repository-denominator, seven-layer readiness, canonical-export, installation, and release claims remain with that root and their native evidence owners. Native LogicGuard closure and repository software-DNA readiness therefore stay separate.

Use the current argument-block hierarchy and one exact child-output-to-parent-input interface for each required contribution. Bind child claim id, parent input node, compatible classifications and scope, consumer status, consumed fingerprint, and native receipt. Material outputs must be consumed or explicitly dispositioned; conflicting durable parents fail.

Bind that model to a separately authored `researchguard.logic.artifact-inventory.v1`. The inventory owns the complete artifact-unit tree, locators, content fingerprints, required resource roles, assets/citations/receipts, parse dispositions, and current observation evidence. Its item denominator comes from a persisted exact request contract and raw artifact-material locator/hash parsed by LogicGuard's closed current adapter on issuance and reload—not from inventory rows or a process cache. The request id is content-addressed, the target revision is the raw artifact subject fingerprint, and the current authority id is bound to the exact material bytes. Production exposes no inventory-to-target authoring shortcut. Co-shrinking the inventory cannot re-sign the unchanged target identity or revision. Missing/changed local bytes block; unreplayable external bytes remain unverified. Structure can be licensed while exact content remains unlicensed; exact prose/layout/assets require current observed bytes and observation receipts.

External expected-target admission fixes the artifact identity and denominator; LogicGuard-native parsing separately interprets the admitted bytes. Anchor and immutable receipt locators/hashes are persistent evidence and cache state is never authority. Direct blueprint use without admission is unverified, and a different target requires a separately admitted anchor. Production has no public or generic target, attestation, or receipt issuer and no inline candidate-authoring path. Impact and reverse trace each perform exactly one current closed native replay over resolved evidence.

Use `researchguard logic blueprint {check|impact|trace|export}` with the same model, inventory, and realization bindings. Impact and reverse trace each run exactly one current blueprint qualification first. If material, authority, structural qualification, or required native depth is failed, stale, unverified, or not run, the result keeps those gaps and does not return an ordinary affected set or complete trace. After admission, impact includes model edges, block interfaces, realization identities, units, resources, content and receipt fingerprints, then follows declared node → block → parent → artifact and projection consumers. Unknown ownership atomically suppresses partial impact. Reverse trace follows artifact unit → block → claims/warrants/evidence → source/citation/native receipt and stops at missing predecessors or native ownership boundaries.

For reverse trace, “first” means before artifact/binding lookup, node indexing, predecessor traversal, cycle detection, or resource resolution. Admission requires both structural `status=complete` and `native_depth_status=current`. Otherwise return one atomic rejected report with `partial_result_suppressed=true`; artifact, node, edge, evidence, source, resource, receipt-terminal, and path fields stay empty while exact qualification/native-depth/material/authority gaps and the claim boundary remain. An unknown artifact id cannot bypass the qualification gate.

A green structural blueprint is not factual truth, content reconstruction, or task closure. Those claims still require the current LogicGuard purpose/depth receipts and exact resource evidence.
