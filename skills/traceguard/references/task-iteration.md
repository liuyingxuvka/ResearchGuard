# Task-Local Trace Iteration

Use the existing independent task loop when later evidence or a future event should test a frozen prediction.

Freeze task id, purpose, coverage and fingerprint, assumptions, unknowns, iteration bound, predecessor receipt, baseline model bytes, expected evidence footprint or future event, expected order when material, and a falsifier before the observation timestamp. Later evidence binds exact observation, evidence, and content fingerprints.

Native proof and development regression use the same frozen trace input and a short structure fixture where a case is sufficient; they do not regenerate a long article or storyline for each check. An introduced gap is a finding about the evidence boundary, not proof of quality improvement. A missing future event, provider, or external observation stays explicitly unavailable with its current gap; no synthetic event or source may fill it.

Compare prediction and observation, create a distinct candidate v2, run the same canonical TraceGuard evaluator and native depth route, then accept, reject, or append a rollback revision. Never overwrite v1 or change solver, rules, thresholds, templates, defaults, or another Guard.

Candidate closure needs a separate holdout observation with disjoint observation, evidence, and content fingerprints. The fitting observation cannot be the holdout. Internal perturbation is not factual future prediction; predictive wording requires the separate target-owned future-holdout validator.

Native comparison and perturbation—not caller prose—produce input, resolved, persisted, and introduced gaps. Continue while predictive or coverage gaps remain. Close only as `model_closed_for_task`; otherwise keep the exact non-closure terminal and next action visible.
