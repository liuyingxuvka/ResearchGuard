# General Trace Route

Use for event/evidence sequences, incidents, requirement history, research lineage, execution and effect chains, competing storylines, counter-scenarios, and bounded causal review.

Model before summarizing:

```text
source lineage -> evidence -> entity mention -> event candidate -> typed temporal/stage relation -> hypothesis -> bounded causal candidate -> canonical inference receipt -> trace/hypothesis projection -> gaps and contradictions -> claim boundary
```

Before candidate construction, freeze one target-local `traceguard.task_model_purpose.v1` with stable model id, prevention purpose, unsupported boundary, selected native failure ids, one task-local known-good, and one known-bad per failure. Packaged cases prove native capability only. Missing, late, stale, mismatched, extra, wrong-instance, or incomplete bindings block. There is one enforced workflow.

For substantive work use layered trace cards: lead, event fact, sequence, mechanism, evidence, counter, boundary, progression, and handoff. Report coverage and keep event fact, explanation, execution/follow-through, outcome/impact, stakeholder signal, counter/delay/non-occurrence, future trigger, and safe wording separate. A clean single storyline is not required when alternatives remain live.

Causal exploration requires typed mechanism, link evidence, confounder disposition, competing alternative, scope, and counterfactual boundary. Chronology and causal words in source text create no causal atom.
