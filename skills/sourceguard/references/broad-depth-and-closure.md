# Broad Source Depth and Closure

Broad, complete, deep, final, or gap-closure wording requires the fixed target-owned chain: family baseline capability, target model-purpose proof, intake, evidence model, gap review, and closure. Every declared check must produce one current terminal-success result for the same exact model and coverage universe.

The universe includes every declared/discovered/required/excluded target unit, critical gap, important branch, required source role, portfolio class, lineage slot, content-bearing anchor, and bridge/provenance need. Every critical gap independently needs direct/primary, independent, and counter/limiting coverage plus explicit lineage. Different source ids from one lineage are not independent. A locator without extracted text or normalized content is not content qualification.

Target-unit inventory cannot shrink to the current model's listed required units. Reconcile every baseline gap structure unit as required or explicitly excluded with non-contribution reason; an excluded active gap blocks. Counts, class lists, catalog expansion, ordinal ranges, or a whole-receipt hash do not prove individual obligations; preserve each native semantic object, evidence reference, and lowercase content hash.

Run current `source depth` and the closure helper after the last model change. `planning_only`, `NOT_RUN`, `PROVIDER_UNAVAILABLE`, `bounded`, stale, skipped, one-gap/one-source, globally diverse but per-gap shallow, missing-lineage, locator-only, or empty-universe results remain bounded. Broad wording requires `adequacy_status: pass`, matched scope, no critical unresolved row, and `broad_claim_licensed: true`.
