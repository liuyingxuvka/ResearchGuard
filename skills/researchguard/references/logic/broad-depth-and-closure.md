# Broad Depth and Closure

Broad LogicGuard wording requires current target-owned evidence over the complete declared argument universe.

Keep three activities separate: native proof for the current task, deterministic regression after a development change, and an independently authorized real-prose/style evaluation. The first two use a task-bound short structure example when a case is needed: one valid target graph plus known-bad variants that remove the declared support or warrant, while retaining the task identity, native oracle, frozen input order, and candidate binding. This fixture tests only the declared structural failure; it does not prove factual truth, prose quality, or a successful real writing run.

Keep model-card coverage, high-importance gaps, skips and safe wording in the native result and a concise task summary. A separate hand-written closure ledger is not required. High-importance claims need connected claim-local support, warrant, assumption, boundary, and opposition or explicit target-authored closed dispositions. Implicitly shared role nodes, unresolved comparable conclusions, untested applicable perturbations, omitted target units/cards, shallow important cards, and a missing competition disposition remain gaps.

Run `researchguard logic depth <model> --output <depth.json>` after the last meaningful model change; it prints the gap summary and writes the full result to the file. Broad claims require the native broad profile and current model plus authoritative-universe fingerprints. Callers cannot raise the importance threshold or shrink the denominator.

Use the current native depth result; do not launch a second closure-ledger checker. `partial`, `blocked`, or `downgraded` results require the named next action or narrower wording. A repository regression proves capability only, never the current task. Broad wording is licensed only when `broad_claim_licensed: true` and all current gaps are closed.
