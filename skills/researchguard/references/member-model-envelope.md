# Member model envelope

Load this reference only for a necessary cross-member blueprint composition, composition impact review, or composition reverse trace. ResearchGuard owns transport and topology only. Each selected member remains the sole owner of its model meaning, checks, terminal, and receipt.

## DNA ownership boundary

This envelope connects independently owned member-domain DNA; it is composition transport, not repository software DNA. The sole ResearchGuard repository software-DNA root is FlowGuard-owned and has exactly four recursively decomposed member subtrees. That root owns repository admission, direct and umbrella routing, composition, envelopes, handoffs, and authority transitions, then binds the member subtrees to implementation, tests, intent, resources, and topology. The envelope supplies only opaque domain identities and handoff evidence. It does not own the repository denominator, seven software-DNA readiness layers, canonical export, installation, or release evidence, and a current envelope cannot close any of those claims.

## Current transport

Require one `researchguard.member-model-envelope.v1` per selected member. It names the same task, member, native model, native schema and version, model and opaque-payload fingerprints, input/output field ids, native receipt references, open gaps, terminal, claim boundary, and source-bound responsibility spans. Separately require exactly one current member-native attestation. The closed registry selects one exact member owner, checker capability, checker version, module, and entry point. That member—not ResearchGuard—parses the opaque bytes and independently replays the exact request, input, result, receipt, and terminal before issuing the transport attestation. ResearchGuard compares the supplied record byte-for-byte with that fresh replay; there is no public generic attestation issuer. A caller-authored passed envelope or structurally self-hashed attestation is never sufficient. Payload bytes may be carried as base64 or omitted; either way the digest is mandatory. ResearchGuard never parses the bytes, imports a member blueprint schema, rescores a receipt, or infers a missing value.

Require one `researchguard.handoff-field-contract.v1` per handed field. It declares one producer envelope and receipt, field schema and payload fingerprint, the complete consumer-requirement denominator, and one current consumed, rejected, or not-run acknowledgement per consumer. A declaration is not proof of consumption. Missing acknowledgement, fingerprint drift, foreign receipt lineage, rejection, or not-run remains visible.

## Operations

- Check: validate exact current schemas, fingerprints, same-task lineage, one envelope per selected member, one producer per field, exact input/output denominators, acknowledgements, and terminal visibility.
- Impact: seed from current envelope, model, receipt, handoff, field, or step identities; invalidate only direct and declared transitive consumers. Any unknown owner blocks confidence and suppresses all partial affected/unaffected lists. Never select `run all`.
- Reverse trace: preserve top-level composition status, blocking member ids, composition gaps, and trace status, then walk from the overall or step claim boundary through step, field, producer/consumer, native attestation, envelope, receipt, and responsibility span. Stop at the native receipt boundary. Invoke the named member if native meaning is requested.
- Export: emit deterministic transport metadata without opaque payload bytes unless explicitly requested. A blocked, failed, stale, skipped, not-run, or non-terminal member is never upgraded by a sibling or by umbrella prose.

The envelope proves transport identity and composition state. It does not prove a member's domain conclusion, reconstruct its internal model, or replace its native good/bad and semantic evidence.

When ResearchGuard invokes a member-native reverse operation, it preserves that member's qualification-first gate: exactly one current member check must complete before target resolution or native closure work. A blocked member report remains atomic—ordinary native trace/path/node/edge/evidence/resource/terminal fields are empty with `partial_result_suppressed=true`—and the umbrella transports only its qualification/authority/material/receipt gaps and claim boundary. ResearchGuard never retries target resolution, supplies a bypass, or turns a sibling's current status into admission.

Target-denominator replay also remains member-native. Each member carries its persisted content-addressed request id, exact target revision, raw-material locator and content hash, then replays those bytes through its own current adapter after serialization. Each reports current, failed, or unverified. The umbrella never parses those bytes, shares a denominator cache, exposes a candidate-to-target authoring shortcut, or turns an external/unreplayable result into readiness.

The externally owned expected-target admission fixes target identity and denominator before member-native parsing begins. Anchor and immutable receipt locators/hashes are persistent evidence; cache state never licenses them. Direct member use without admission remains unverified, and a different target requires a separately admitted anchor. There is no public or generic target, attestation, or receipt issuer and no production inline candidate-authoring path. Impact and reverse trace each run exactly one closed member-native composition replay over resolved evidence.
